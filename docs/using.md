# 설치하고 확인하기

## 1. Chrome이 사용자 스크립트를 허용해야 합니다

이것이 없으면 **아무 스크립트도 등록되지 않습니다.** Chrome이 확장별로 사용자에게 직접 켜게 하는
스위치이고, 확장이 대신 켤 수 있는 API는 없습니다.

1. `chrome://extensions` 를 엽니다
2. **AXSDK Assistant** 를 찾아 **세부정보**
3. **사용자 스크립트 허용** 을 켭니다

확장 설정 화면의 **Community scripts** 항목이 이 상태를 그대로 알려줍니다.

| 화면 문구 | 뜻 |
|---|---|
| Community scripts can run in this browser. | 준비됨 |
| Chrome's "Allow user scripts" is off for this extension. | 위 스위치가 꺼져 있음 |
| Chrome refused the user-scripts API for this extension. | API 이름은 있지만 Chrome의 확인 호출이 거부된 드문 상태; 화면에 실제 오류 문구가 함께 나옵니다 |

**Chrome은 이 스위치가 바뀌어도 확장에 알려주지 않습니다.** 그래서 **Check again** 버튼이 있습니다 —
스위치를 켠 뒤 이걸 누르면 페이지를 새로 고치지 않아도 반영됩니다.

## 2. 스크립트 설치

설정 화면의 **Install from a manifest URL** 에 매니페스트 URL을 붙여넣고 **Look it up**.

요약이 나타납니다. **첫 줄이 출처 URL**입니다 — 서명이 없으므로 그 URL이 유일한 출처 증명이고,
승인 전에 반드시 확인해야 하는 한 가지입니다.
`publisherId` 와 `reviewerId` 는 URL 제공자가 쓴 메타데이터이지 서명으로 검증된 신원은 아닙니다.
이름만 보고 신뢰하지 말고 URL과 공개 소스를 확인합니다.

요약이 보여주는 것:

- 이름·버전·**발행자**·**검수자**·라이선스
- **Runs on** — 이 스크립트가 붙는 페이지 패턴
- **May fetch from** / Reaches no network hosts — 접속할 수 있는 호스트
- 명령 목록과 각 명령의 `[effect]`, 그리고 `asks you first` 표시

**Install** 을 누르면 설치되지만 **꺼진 상태**입니다. 목록에 나타나고 버튼이 **Enable** 로 보입니다.
켜려면 그 버튼을 누릅니다.

> 사용자 스크립트 스위치가 꺼져 있으면 **Install 버튼이 아예 나타나지 않습니다.** 등록될 수 없는
> 설치는 하지 않습니다 — 기록만 남고 영원히 실행되지 않는 상태를 만들지 않기 위해서입니다.

## 3. 켜고 끄기

목록의 각 항목에 **Enable** / **Disable** 이 있습니다.

- **켜는 것은 모든 검사를 통과해야 합니다** — 브라우저가 준비되어야 하고, 폐기된 릴리스는 켤 수 없습니다
- **끄는 것은 항상 됩니다** — 후회한 스크립트에서 빠져나오는 길이 브라우저 상태에 달려 있으면 안 됩니다

## 4. 사용하기

에이전트를 시작하고 대화로 요청합니다. 두 가지 경로가 있습니다.

### 인자가 없는 읽기 → 한 턴에 답변

`read` 이면서 필수 인자가 없는 명령은 **턴 전에 미리 실행되어** 결과가 모델의 컨텍스트에 들어갑니다.
그래서 *"이 페이지 뭐라고 쓰여 있어?"* 같은 질문에 한 번에 답합니다.

> **네트워크 호스트를 선언한 릴리스는 사전 실행에서 제외됩니다.** 요청하지 않은 턴이 사용자를 대신해
> 외부 요청을 보내면 안 되기 때문입니다. 그런 스크립트의 읽기는 아래처럼 **명시적으로 요청**해야
> 합니다.

### 그 밖의 명령 → 버튼으로 승인

인자를 받거나, 사전 실행 대상이 아닌 명령은 확인 버튼이 됩니다.

```
Fixture Page Reader (axsdk-fixtures) 의 remember 을(를) 실행할까요?
Store a short note … [read] 전달할 값: {"note":"메모"}
[ remember 실행 ]
```

누르면 버튼이 잠시 비활성화되고, 끝나면 **결과가 버튼 아래에 표시됩니다.** 실패나 거부도 같은
자리에 나옵니다.

### 문구 요령

플래너가 어느 기능으로 보낼지 고르므로, 커뮤니티 스크립트를 쓰려면 **스크립트를 지목**하는 편이
확실합니다.

```
run remember from the community script installed on this page with note "메모"
```

*"기억해줘"* 처럼만 말하면 확장의 메모리 기능으로 갈 수 있고, *"read_heading 실행해줘"* 는 페이지
읽기 기능으로 갈 수 있습니다. **"…from the community script installed on this page"** 를 붙이면
커뮤니티 스크립트로 갑니다.

## 5. 스크립트가 할 수 없는 것

| | |
|---|---|
| 선언하지 않은 페이지에서 실행 | 등록 자체가 되지 않습니다 |
| 선언하지 않은 호스트로 요청 | `net_host_undeclared` 로 거부 |
| 선언하지 않은 명령 실행 | `command_undeclared` 로 거부 |
| 스키마에 맞지 않는 인자 | `arguments_invalid` 로 거부 |
| 코드를 더 받아오기 (`eval`, `import()`, `<script>` …) | 설치 시점에 거부 |
| 페이지가 스크립트의 저장소를 읽거나 지우기 | 불가 — 저장소는 확장 쪽에 있습니다 |
