Operational + architectural guide for agents working in this repo. This file is **gitignored**
(local context, never published), so it may hold dev-environment detail. The **rest of the repo is
public** — apply the public-safety rules below to every committed file. Never paste secret values

## 1. What this repo is

Site-specific data + Lua automation that the **AXSDK Chrome extension** loads to drive real websites
on a user's behalf (search, read, fill forms, request quotes, shop). Each top-level `<site>/`
directory holds that site's `llms.txt`-style sitemap data and AXSDK Lua scripts; `_common/` holds
the shared, site-agnostic base. The extension fetches these from GitHub
(`raw.githubusercontent.com/layorixinc/axsdk-sites/main/...`) at runtime.

Published sites (see `index.md`, keep it in sync): **amazon**, **thumbtack**, **bluemoonsoft**
(`docuray/` is an empty placeholder — not supported data).

### Gitignored (never committed)
`AGENTS.md` (this file) · `.env` (holds `AXSDK_API_KEY` and friends — **secret**) · `dist/`
(generated by `npm run build:lua`) · `*.legacy.yaml` (working backups).

## 3. The Lua runtime model (how the extension runs this code)

- **Layered load order.** The extension injects Lua **per directory, in filename order**: the shared
  base in `_common/scripts/*` **first** (registered `kind:'common'`), then each `<site>/scripts/*`
  once that site's domain is active. Numbered prefixes (`00_`, `10_`, …) pin the order.
- **Globals are the only cross-file channel.** `_common/scripts/00_base.lua` sets `AX_BASE = {...}`;
  site files do `local B = AX_BASE` and expose `AX_<SITE>` (e.g. `AX_THUMBTACK`) plus public
  `AX_*` commands. Each file is its own chunk (locals/`return` are file-scoped).
- **`_common` survives off-domain navigation.** Common scripts stay loaded when you leave a site, so
  cross-domain entry points work anywhere (e.g. resolve a ZIP on google.com, then open a provider).
  Site scripts are cleared on off-domain nav and re-fetched when you return.
- **Build/bundle:** `npm run build:lua` → `dist/_common.lua` + `dist/<site>.lua` (site-only, load
  AFTER `_common.lua`). `npm run build:lua:self-contained` prefixes each site bundle with `_common`
  so it runs alone. `npm run build:lua:check` validates. `dist/` is gitignored.

### Re-entrant page-detect model (the rebuild — see `thumbtack/CONTRACT.md`)
The key live finding: **every page navigation is a full reload that destroys the Lua context**, and
resuming a Lua call across it via the SDK's durable cross-nav is slow (measured 12–21s spikes).
Design rules:
- **Page-level tools are re-entrant + page-detecting.** Each call: detect the current page; if at
  the target, read & return `status:"done"`; if a nav is needed, **fire it and return immediately**
  (`status:"navigating"`) — never await across the reload. The caller (flow self-loop / harness)
  re-invokes; `detect_page` then sees the new page. Idempotent + self-healing (a fire-and-forget
  click that didn't navigate is simply re-fired next call).
- **Same-context overlays run in one call.** The Thumbtack quote dialog is an SPA overlay
  (pushState, no reload), so the multi-step form wizard runs within a single Lua call.
- **Reads are selector-first with per-field fallback chains.** Each field = an ordered list of
  candidate selectors (`data-test` → semantic/structural, first non-empty wins); missing field → null
  (partial, never hard-fail); record which selector fed each field so drift is visible. URL supplies
  IDs/zip. JSON-LD/Apollo were dropped as primary sources.

## 5. Dev Chrome + CDP (the live environment)

The harness drives a **dedicated dev Chrome** over the Chrome DevTools Protocol. Canonical config
(all overridable by env; defaults live in `tools/harness/cdp.mjs`):

| thing | value | env |
|---|---|---|
| CDP port | **9224** | `CDP_PORT` |
| profile | `%LOCALAPPDATA%/AXSDKSitesChromeDevProfile` (persists login + extension) | `CHROME_PROFILE` |
| chrome | `C:/Program Files/Google/Chrome/Application/chrome.exe` | `CHROME_PATH` |
| extension id | `dldlgmekahifbogjphgglkhibclglmpf` | `AXSDK_EXTENSION_ID` |
| extension build | `../axsdk-sdk-js/packages/axsdk-extension/dist` (sibling repo) | `AXSDK_EXTENSION_PATH` |

Launch flags that matter: `--remote-debugging-port=9224 --remote-allow-origins=*`
(the `*` is **required** for the Node WebSocket to attach), `--user-data-dir=<profile>`,
`--load-extension=<dist> --disable-features=DisableLoadExtensionCommandLineSwitch` (so a fresh
profile still gets the extension). **Never** pass `--enable-unsafe-extension-debugging` — it makes
the CDP HTTP endpoint respond but the WebSocket connect fail.

- `window._AXSDK` / `window._AXLUA` exist only in **debug mode** and only in the **content-script**
  context named **`AXSDK Assistant`** (origin `chrome-extension://<id>`) — not the page world.
- `lua.run(cmd, args, {timeoutMs})` = durable path (handles nav/reload); returns `{status, deferId,
  result}` where `result` is a JSON string. `lua.call(cmd, args)` = single turn (navigating steps
  return a pending marker). `lua.load(src, {id})` / `lua.loadSiteScript(...)` inject Lua in-memory.
- Login required → commands return `status:"login_required"`.

## 6. ★ The daily live harness: `tools/ax.mjs` (`ax`)

**Use this for day-to-day work.** One command launches/attaches the dev Chrome, finds the AXSDK
context, and runs any `AX_*` command against the tab you're looking at — **no DevTools console, no
git push, no extension reload.** Built on `tools/harness/cdp.mjs` (the single source of CDP/Lua
plumbing). Verified working end-to-end (Chrome 149, port 9224).

```bash
node tools/ax.mjs chrome [site|url]    # ensure dev Chrome is up (launch detached if down)
node tools/ax.mjs open  <site|url>     # navigate the dev tab (thumbtack|amazon|bluemoonsoft|url)
node tools/ax.mjs load  [site]         # inject LOCAL working-copy Lua (_common + <site>) — site auto-detected
node tools/ax.mjs run   <CMD> [json]   # durable lua.run; prints parsed result   (--local = load first)
node tools/ax.mjs call  <CMD> [json]   # single lua.call turn (read-only checks)
node tools/ax.mjs page                 # current url + quick AX_read_page situational read
node tools/ax.mjs ls | status          # lua.listCommands() / lua.status()
node tools/ax.mjs repl                 # interactive loop (".help" for meta-commands)
```
npm aliases: `npm run chrome`, `npm run repl`, `npm run ax -- <args>`.

**Typical loop (edit Lua → see it live):**
```bash
node tools/ax.mjs open thumbtack
# edit thumbtack/scripts/search_service.lua ...
node tools/ax.mjs --local run AX_search_service '{"query":"house cleaning","zip_code":"94101"}'
```
`--local` / `ax load` reads the working copy and injects `_common/scripts/*` then `<site>/scripts/*`
(filename order), **overriding** the GitHub-fetched scripts in the live runtime (`ax ls` shows
`overriddenBy: ax-local-...`). This sidesteps the cache-stickiness problem in §9. Overrides are lost
on the next full navigation — just re-run `ax load` / `--local`.

Flags: `--port`, `--cdp`, `--chrome`, `--profile`, `--extension-id`, `--extension`, `--match=<url
substr>` (pick a tab), `--site=<slug>` (force site for `load`), `--timeout=<ms>`, `--no-launch`.

> The `ax` CLI is the canonical shared-plumbing path. The heavy E2E runner
> `thumbtack/scripts/test_thumbtack_lua.mjs` still has its own copy of the CDP primitives and is a
> candidate to migrate onto `tools/harness/cdp.mjs` later.

## 7. ZIP / locale resolution (US-only)

`AX_resolve_zip` / `B.resolve_zip` ladder (layered, no single load-bearing source):
explicit 5-digit `zip_code` → embedded ZIP in `address` text → **forward geocode** (Photon/Komoot
primary, Nominatim/OSM fallback) **+ Census ZCTA reverse** (robust for `"City, ST"` and full
addresses) → Census `onelineaddress` (full street only) → error. No API key required. Returns
`{zip_code, source}` | `{error,...}` | `{pending}`. (Zippopotam was the old primary and was
**replaced** — it mis-resolved some cities, e.g. "San Francisco" → "South San Francisco".)

## 8. Testing & verification

Prefer **`ax`** for Lua iteration (§6). Other tools:

- **E2E scenario runner** `thumbtack/scripts/test_thumbtack_lua.mjs` (CDP, port 9224 default):
  ```bash
  node thumbtack/scripts/test_thumbtack_lua.mjs --multi-quote --quote-count=2 --submit-quote --max-quote-steps=20 --keep-open
  node thumbtack/scripts/test_thumbtack_lua.mjs --scenario="handyman|San Francisco, CA" --actual-submit --keep-open
  ```
  `--submit-quote` progresses to the final Submit with reserved/fake contact data but **never clicks
  it**; `--actual-submit` clicks it (only when intentional). Logs each tool call with elapsed/wall
  time, flags `[SLOW >3s]`. Other `test_*.mjs`/`verify_*.mjs` cover specific units (open-quote
  durability, beforeunload, form wizard, detect_page, read_page, resolve_zip, …).
- **Offline Lua unit tests** (deterministic logic: serialization, parsing, normalization, dedupe):
  use a `fengari` unit test and mirror the SDK's real Lua→JS converter (sequence detection + the
  array-type marker); `lualib.luaL_openlibs(L)` is needed for `tostring`/string lib. A custom reader
  that ignores the marker gives false confidence.
- **Cost discipline:** a full live multi-step flow run costs minutes (nav + per-model-call). Iterate
  with reduced scope (one item / lowest count) and confirm full scope once at the end.

### Performance bar (Thumbtack multi-quote, hard-won)
Per-step `< 3s`, full `--multi-quote --quote-count=2` `< 30s` (median ~25–29s; tail variance is live
page-load, not the code). Levers that got there: **two-phase search** (fire submit → CDP-wait for
results → read, so no Lua call suspends across the results reload), bounded waits (no blanket 30s
selector ceilings, no 2.5s blind settles), retry caps (no retry storms), a **load-once cache** (skip
re-loading the 14 Lua files when the context isn't dirty), clean hard-nav per item, and passing the
resolved `zip_code` into search to skip a re-fetch.

### Testing flow (`flows.yaml`) changes — without pushing
`raw.githubusercontent.com` is cache-sticky, so **test flows from the store with remote flows OFF**:
- Turn remote OFF (authoritative store): `AXSDK.config.clientFlows = { remoteSites:false, stored:true }`
  (or the Options toggle). If remote stays on, it is re-fetched/deep-merged on nav and silently
  overrides your edit.
- Inject local flows: `AXSDK.getFlowsStore().getState().setFlows(":", "<yaml>")` (key `:` = common
  flows; `:<domain>` = a site's). Equivalent: persist `chrome.storage.local["axsdk:flows"]` =
  `JSON.stringify({state:{flows:{":":"<yaml>"}},version:0})`, or use the Options Flows editor.
- Drive the engine: `AXSDK.sendMessage(text)`, poll `AXSDK.getChatStore().getState()` (assistant
  message in the last message's `parts[]`: tool parts carry `state.output`; the terminal reply is a
  `type:"text"` part — messages have no `role` field).
- Scope: this overrides **flows only**. Site **Lua** still loads from GitHub on nav — use `ax load`
  (or `lua.load`) to iterate Lua without a push.

## 9. Gotchas

- **New Lua file** → loads after a cache-bust reload (DevTools → Network → Disable cache → reload),
  confirm with `lua.listCommands()`. **Editing an existing file is stickier**: the site definition is
  cached in `chrome.storage.local["axsdk:sites"]` and site scripts re-apply by script id (not source
  hash), so an edited same-name file can keep serving the old source even after a cache bust →
  **reload the extension** (chrome://extensions → reload) to force a clean re-fetch. **Easiest:
  `ax load` / `ax run --local`** to inject the working copy directly (§6).
- **`run` vs `call`:** prefer durable `run`; `call` is one turn and returns a pending marker for any
  navigating/fetching step.
- **`beforeunload` dialog** (unsaved quote/form state) blocks navigation and caused CDP timeouts; the
  harness auto-accepts dialogs (`Page.handleJavaScriptDialog {accept:true}`). Manual testers click
  "Leave".
- **Cross-nav durable resume is slow** (12–21s) — that's *why* tools are re-entrant + fire-and-return
  (§3); don't reintroduce single calls that await across a page reload.
- **Navigation changes the context id** — the harness re-finds the `AXSDK Assistant` context every
  call (so does `ax`). After a nav in DevTools, re-select the context or just re-run.
- **Empty Lua table → JSON object, not array.** A flow-state field a tool schema validates as `array`
  then fails `expected array, received object`, and the array-type marker isn't reliably honored on
  every output path. For LLM-tool-validated state prefer a scalar (e.g. a newline-joined string
  accumulator) and split it in the consumer.
- **Cross-domain helpers must live in `_common/scripts/`** (`kind:'common'`) so they survive the
  off-domain site-script clear; `<site>/scripts/*` do not.

## 10. Lua script authoring rules

### Selectors (stability across deploys / A/B variants)
The `dom` capability resolves **standard CSS only** (`querySelector`/`querySelectorAll`) — **no text
matching, no XPath**.
- **Never** target obfuscated/build-generated class hashes — CSS-module/styled-component names like
  `._2Wt7kayvRID5rLVjUZGxyx`, `.css-1a2b3c`, `[class*="_3iW9"]`. They change every deploy and differ
  across A/B variants.
- **Prefer** stable identifiers: `data-test`/`data-testid`, word-based `id`/`name`, `aria-label`,
  `role`, semantic elements (`main`, `aside`, `section`, `nav`, `form`), design-system utility
  classes made of real words.
- No stable id? Locate by **document structure/position** relative to a semantic anchor:
  parent/child/sibling combinators, `:has()`, `:not()`, `:nth-*`, `:first/last-child`.
- **Label-only elements:** `dom` can't match by visible text → `dom.query_all(sel, {text=true})`,
  confirm the label in Lua, then click the verified selector.
- Keep shared selectors as named `M.*` constants in `<site>/scripts/00_common.lua` (reviewed in one
  place).
- **List/result cards:** the same label is often rendered more than once (responsive duplicates) and
  may carry trailing badges (`Top Pro`, `Very good`, `Exceptional`, `Great`). Collapse the largest
  immediately-repeated prefix and strip known trailing badges before using a card value
  (`B.dedupe_adjacent` helps).

### State & serialization
See the empty-table-→-object gotcha in §9. Use scalars for tool-validated state.

## 11. Constraints & conventions

- **Public data only** in committed files. Never commit secrets, tokens, cookies, internal URLs,
  customer data, credentials, or PII. Treat the repo as public on GitHub.
- **Never auto-submit / send a quote.** Flows stop before final submission; only `Next`/`Continue`/
  optional `Skip` are clicked automatically. `AX_submit_quote` requires explicit `confirm:true`.
  `AX_checkout` never places an order.
- **Test data:** use only reserved/fake values in dev — `thumbtack-test@example.com`, `415-555-01xx`,
  a public ZIP like `94101`. Never real PII.
- **Factual + source-based.** Don't invent URLs/metadata/capabilities. Prefer canonical, stable URLs;
  strip tracking/session/localized params unless required for the resource to work.
- **Small, reviewable changes**, no unrelated churn. Preserve existing naming/directory conventions;
  don't add a `sites/` wrapper. Lowercase host/slug dir names, no `https://` in paths.
- **Keep in sync:** `index.md` with populated sites; `SCHEMA.md` (simple array: `name`,
  `description`, `parameters` only — no output schemas/shared types); `DEVTOOLS.md`;
  `thumbtack/CONTRACT.md` (re-survey when Thumbtack changes).
- **Git identity:** `lordkeios <lordkeios@lilysnc.com>`. Default to commit-only; push only to ship a
  verified change (durable multi-nav fixes must be pushed to `origin/main` because the extension
  fetches scripts from GitHub).
- **Style:** plain UTF-8 Markdown, concise and operational, English for repo-wide technical guidance
  (a narrower file may use another language — `index.md` is Korean).

## 12. Validation before reporting work complete

- Re-read every file you changed.
- Confirm public-safety: no secrets, private endpoints, or PII in committed files.
- Confirm URL accuracy against the source when adding/updating site data.
- Run available checks: `npm run build:lua:check`, `node --check <changed>.mjs`, the relevant
  `ax`/`test_*`/`verify_*` run, or an offline `fengari` unit test. If no check exists for what you
  changed, say so in the final response.
