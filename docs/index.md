# AXSDK 커뮤니티 스크립트

AXSDK 확장은 **당신이 설치한 스크립트**로 웹페이지를 읽고 조작합니다. Tampermonkey와 같은 방식이지만
차이가 하나 있습니다 — 스크립트를 **당신이 직접 실행하는 대신, 대화로 요청하면 AI가 명령을 골라
제안하고 당신이 버튼을 눌러 승인합니다.**

- [설치하고 확인하기](using.html) — CWS에서 받은 확장이 제대로 동작하는지 확인하고, 스크립트를 설치·사용하는 법
- [스크립트 저작하기](authoring.html) — 매니페스트와 스크립트를 쓰고, 파일을 배치하는 법
- [개발과 디버깅](debugging.html) — 무엇이 어디서 거부되는지, 왜 조용히 아무 일도 안 일어나는지
- [배포하기](hosting.html) — GitHub Pages로 스크립트를 남에게 설치 가능하게 만드는 법

## 이 시스템의 규칙 네 가지

읽기 전에 알아두면 나머지가 전부 설명됩니다.

**1. 스크립트는 서명되지 않습니다. URL을 고른 사람이 책임을 집니다.**
설치할 때 매니페스트 URL을 직접 붙여넣습니다. 확장은 서명을 검사하지 않는 대신, 매니페스트가
**선언한 것과 받은 파일이 같은지**(SHA-256), 스크립트가 **코드를 더 받아오려 하지 않는지**, 그리고
출처가 **https 인지**를 검사합니다.

**2. 설치는 실행 허가가 아닙니다.**
설치된 스크립트는 **꺼진 상태로** 들어옵니다. 켜는 것은 별도 행동입니다.

**3. 명령마다 무엇을 할 수 있는지 미리 선언합니다.**
어느 페이지에서 동작할지(`matches`), 무엇을 하는지(`effect`), 어느 호스트에 접속할지
(`network.hosts`), 어떤 인자를 받는지(`inputSchema`). **선언하지 않은 것은 거부됩니다** — 매번,
호출 시점에 다시 검사합니다.

**4. AI는 명령을 제안할 뿐입니다.**
인자를 받는 명령이나 변경을 일으키는 명령은 **버튼**이 되어 화면에 나타납니다. 누르는 것은
당신이고, 누른 뒤 결과가 버튼 옆에 표시됩니다.

## 지금 상태에 대한 정직한 안내

이 문서가 설명하는 경로는 실제로 동작하며 라이브로 검증됐습니다. 다만 아직 준비 중인 것도 있습니다.

| | 상태 |
|---|---|
| 설치·활성화·명령 실행·버튼 승인·결과 표시 | 동작함 |
| 스크립트 저작·자체 호스팅 | 동작함 (이 문서가 그 방법입니다) |
| 업데이트 승인 UI (권한 증가 강조) | **동작함** — 새 호스트·새 effect·코드 변경을 별도로 보여주고 승인을 받습니다 |
| 원격 폐기·제거 UI | **없음** — URL 설치 경로에는 폐기 피드가 없고, 문제가 있는 스크립트는 우선 Disable 해야 합니다 |
| 설정 화면의 개발자용 항목 정리 | **미완** — 지금 빌드에는 일반 사용자에게 필요 없는 입력란이 함께 보입니다 |
